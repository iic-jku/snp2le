# snp2le: architecture and developer notes

For what the tool does and how to install and run it, see the main [README](../README.md). This file covers what the README does not: how the code is organised, the data flow, how to extend it, and the internal caveats.

`snp2le` is one package split into a pure-Python, Qt-free `snp2le.core` (fully testable) and a thin `snp2le.gui` on PySide6-Essentials, wired together by the single entry point `engine.convert(state, net)`. The module map is the README's [Directory Structure](../README.md#directory-structure).

The GUI uses only `QtCore`, `QtGui`, `QtWidgets` and `QtSvg`, so the declared dependency is `PySide6-Essentials`, not the full `PySide6` metapackage. The latter drags in PySide6-Addons (QtWebEngine, Multimedia, Charts, ...), roughly 400 MB that nothing here imports. This matters for container images such as IIC-OSIC-TOOLS. Keep it that way: a bare `from PySide6.QtCharts import ...` would still work on a developer machine that happens to have the metapackage installed, but would break an Essentials-only deployment. A full `PySide6` install satisfies the requirement too, since the metapackage depends on `PySide6-Essentials`.


## Data flow

The flow is always **load, `engine.convert(state, net)`, `Results`, views**:

1. `io.load_touchstone` reads the `.sNp` (scikit-rf), and `engine.convert` then refers every port to one real reference through `io.uniform_reference` (see Notes / limitations), drops any 0 Hz sample through `io.without_dc` and restricts the data to the requested fit band through `io.restrict_band` (`state.f_min` / `state.f_max`, both optional). In universal mode the file's 0 Hz sample goes on in two ways: as `dc_net`, the band with it, for a refit in passivity enforcement, and as the target of the DC pin (`dcpin.py`), appended after the fit. Everything downstream, the RMS error, the plots and a testbench run's sweep, refers to the fitted band.
2. `engine.convert(state, net)` runs the chosen mode and returns a `Results` dataclass: the IR, both rendered netlists, the data-vs-model S-parameters, element values, tolerances and messages.
3. The GUI (`design_view`, `plot_view`) and the CLI both render from that one `Results`, so what you see and what you export always agree.


## Progress and threading

`engine.convert(state, net, progress=None)` takes an optional `callback(fraction, message)` and reports an overall 0..1 along the way. `core/progress.py` holds the two pieces around that contract: `StageTracker` maps a stage's own 0..1 onto its weighted slice of the whole run (the weights live in `engine._PLAN_UNIVERSAL` / `_PLAN_STRUCTURE`), and `ProgressReporter` is a thread-safe sink that also keeps the elapsed time (no time-remaining estimate, see `progress.py`). Core stays Qt-free: the reporter is plain `threading`.

`engine.convert` runs the whole conversion on one BLAS thread (`engine._one_blas_thread`, threadpoolctl 3.5 or newer, the first release that finds the scipy-openblas libraries of numpy 2 and scipy wheels). The matrices are small, and with the default 14 threads on a hybrid laptop CPU a 7-port core at order 24 with thermal noise converted in 905 s against 2.2 s on one thread. threadpoolctl changes the loaded libraries at run time and restores them afterwards, where environment variables would also reach every simulator snp2le starts. An explicit `OPENBLAS_NUM_THREADS` or `MKL_NUM_THREADS` turns the limit off, and so does a missing threadpoolctl. Conversions that overlap in threads share the limit through `process_state.ProcessSetting`: the first one in sets it and the last one out restores the count the process had. A save-and-restore per call left a program that ran 16 conversions in 8 threads on one BLAS thread for good, since the second conversion saved the first one's limit as the original. One thread gives the same result as an `OPENBLAS_NUM_THREADS=1` run of 0.1.11 in every record of the option-space dump. Against 0.1.11 at 14 threads the universal netlists of the bundled examples were unchanged at the 10 digits 0.1.12 printed, while a few wideband inductor fits settle elsewhere along their weakly determined values, the same kind of move another numpy or scipy makes.

Three parts of the pipeline report from inside, which is what makes the fraction track real work rather than count steps:

* `mna.rlc_sparams` reports per frequency (one MNA solve each), which dominates a structure-mode conversion over a wide EM sweep.
* `universal._fit_watch` reports during `auto_fit`. scikit-rf offers no callback there, but it appends to `vf.d_res_history` once per pole-relocation iteration, so a watcher thread polls that length. It is a real signal and needs no log scraping, which is the brittle route `_enforce_passivity` already avoids. The iteration count is not known in advance, so the reported fraction follows a saturating curve and deliberately stops short of 1.
* The wideband inductor fit (`structures/inductor_fit.py`) knows in advance how many least-squares runs it will make and reports after each one. It runs under its own plan, `engine._PLAN_STRUCTURE_WIDEBAND`, where the fit is 92 % of the weight, so the fractions of every other structure are unchanged.

On the GUI side, `gui/fit_runner.py` runs `engine.convert` on a `QThread` and `gui/fit_status.py` renders the indicator. It is hosted twice, in the Design view's Conversion panel and (compact) in the Plot view's header row, so a running fit is visible in either view without either one growing: both hosts had spare room. `MainWindow._fit_indicators` is the list the tick drives. Two rules there:

* **One fit at a time, newest wins.** A request arriving mid-fit is remembered, not queued, so dragging a spin box starts one more conversion, not one per value. `MainWindow._res` caches the finished `Results`, and Export writes that instead of re-converting on the GUI thread.
* **Progress is sampled, not pushed.** The worker updates the reporter and `MainWindow._fit_clock` reads `snapshot()` every 80 ms. No Qt signal crosses the thread boundary except `finished`, and the elapsed display keeps ticking even while the fit sits inside one long scikit-rf call.

A QThread destroyed while running aborts the process, so `FitRunner.shutdown()` waits, and parks a worker that outlives the wait in `fit_runner._ORPHANS`.


## Adding a structure

Subclass `snp2le.core.structures.base.Structure`, implement `extract(net, ...)` returning `(CircuitIR, metrics, rows)`, and register it in `snp2le/core/structures/__init__.py`. It then appears in the GUI dropdown and the CLI automatically. The registry order is the dropdown order. Structure mode opens on `structures.default_structure(n_ports)`, the first entry with the file's port count that is not a wideband fit, which keeps a slow fit from starting on its own. The three inductors lead the dropdown, and a 3-port still opens on the in-phase Wilkinson. Notes for the message line go in `metrics["messages"]`, which the engine moves into `Results.messages`.

A structure fitted over the whole band instead of read off at f_ext sets `wideband = True`. The engine then calls its `extract()` with `progress` (a `callback(fraction, message)` for the extract stage) and the fit options of `inductor_wideband.wideband_options(state)` as keywords, skips the f_ext range note, and passes the IR to `freq_traces()` and `default_plots()` so their views can follow the fitted port order. The GUI shows its own page in place of f_ext (`TopBar.wide_page`), the Result panel shows `metrics["f_fit_max"]` as *fitted up to*, and the CLI prints the fit band and `metrics["segments"]` in place of f_ext.

## Notes / limitations

* Verifying the final netlist (re-simulating it against the original) is done in your own flow (Xschem / Ngspice / VACASK). The GUI can drive it (Load .sch, Run Simulation), but the simulators themselves are not bundled.
* For a universal macromodel the DC operating point is checked. A linear model only fails to solve if the network is singular (a floating internal node), and the result flags that before you hand the netlist to a simulator.
* In VACASK the subcircuit ground is node `GND` (Spectre has no implicit node-0 ground), so the testbench must declare `ground GND`. Ngspice keeps node `0`. High-order universal fits are conditioned automatically so VACASK reproduces the same response as Ngspice.
* VACASK's builtin `mutual` takes k from 0 to 1 only, while the balun extracts a negative k. `netlist._vc_swapped_coils()` picks a terminal order per coupled coil that makes every k positive, which is the same circuit, and the VACASK header names the swapped coils. The Ngspice netlist keeps the negative k, which Ngspice accepts. The bundled VACASK testbenches declare `model mutual mutual` for the balun and the wideband inductors. The balun's VACASK response matches Ngspice's to 1.5e-7 in S.
* `is_passive()` may report borderline-False even after enforcement on a good fit. The model is still usable. The status is reported honestly ("near-passive").
* Passivity is also reported as a number. `universal.max_singular_value()` returns the largest singular value of the fitted S-matrix over a grid that spans four decades either side of the data and is refined inside the violation bands `passivity_test()` reports. `ConverterState.passivity_ceiling` (1.0 to 1.2) is the sigma_max the enforcement works towards, not merely an acceptance threshold: the model really is perturbed down to it, which trades a bounded violation for a fit up to a few times more accurate than strict enforcement gives. sigma_max(S) <= t is exactly sigma_max(S/t) <= 1, so `universal._enforce_at()` scales the rational model by 1/t, runs scikit-rf's standard perturbation, and scales back. At t = 1.0 both scalings are the identity, which is what keeps the strict path bit-for-bit what it was. A ceiling the residue perturbation cannot reach (an unbounded violation band, from a non-passive constant term) leaves the accurate fit in place instead. When perturbation fails, `_enforce_passivity_path()` tries a lower-order refit and, for a file with a 0 Hz point (`dc_net`), a refit at the same order that includes it, enforced the same way. Each counts only if it clears the ceiling and still fits the data (`_USABLE_RMS`), and the closer one wins. scikit-rf meets the 0 Hz point through the constant term, so the refit lands on other poles and residues and often clears the ceiling where the free fit's D ran past 1. It does not bound D in general (with a DC point prepended, the WPD at order 6 still fits D at 5.06), it is one more candidate. Like the lower-order refit, a passing one replaces the accurate near-passive fit under the `_USABLE_RMS` rule, at an error 12 times larger in the median over 130 ORCA runs and 525 times on the bundled 500 pH coil with a DC point at order 6 (7.0e-5 to 3.7e-2). With `prefer_strict` (the engine sets it for thermal noise) candidates rank strictly passive first, then by RMS: at ceiling 1.05 the refit can land just above sigma 1 and beat a strictly passive lower-order refit, which cost two ORCA coils their noise generator until the rule. On the bundled examples with a DC point prepended, the balun and the 500 pH coil at order 6 go from near-passive to passive, and `tline_100um` at order 13 does too, with scikit-rf 1.12 and 2.1.0 alike. Without `dc_net` the branches and messages are those of 0.1.13. With it a failed perturbation costs one more fit and its enforcement, about twice the conversion time on the 3-port ORCA coils at order 40 (2.0 s to 3.8 s), reported on its own share of the progress bar, and a refit that does not settle reports that only when it is the one kept. `dc_net` exists when the fitted band starts at the file's first sample above 0 Hz, and not for a 0 Hz row that is not finite. Its 0 Hz point is clipped to sigma `dcpin.DC_SIGMA` = 1 - 1e-6, the pin's own clip: a coil's open common mode is a sigma of exactly 1 there, the refit meets it, and a model at sigma 1 has no spectral factor, so 5 of 20 ORCA coils at order 40 lost their thermal noise to the refit until the clip. Without `max_order` the refit runs at the fit's own model order. scikit-rf's `passivity_enforce` writes only the residues (1.12 and 2.1.0 alike), so the constant term D, the model's value at infinite frequency, is out of its reach. `universal.constant_term_sigma()` measures D, and a final model whose D is above its ceiling gets a message that names D and the knob that is left, another Max order. `Results.passivity_path` says which branch produced the model (`off`, `not needed`, `perturbed`, `reduced order`, `dc refit` or `near-passive`, empty for a structure model), so a caller need not read it out of the messages. `universal._enforce_passivity()` keeps its three return values for callers outside snp2le, `_enforce_passivity_path()` adds the path. 1.0 is the floor because a lossless reciprocal network sits at exactly 1. An out-of-range number is clamped to the edge it overshot and a non-number falls back to the default (`universal.clamp_passivity_ceiling()`), so the GUI field answers "what is the limit" by showing it. The rule that the ceiling applies only while enforcing lives in `universal.effective_ceiling()` alone, so the GUI, the CLI and the engine cannot disagree about it.
* `ConverterState.max_order` is a model order, `n_real + 2 x n_complex`, and it reaches scikit-rf as `auto_fit(model_order_max=...)`. `Results.model_order` is that same count measured on the fitted poles, and it is the number of internal states per port in the netlist (an N-port has N times that), since a conjugate pair costs `x_re` and `x_im`. `Results.n_poles` counts pole entries, where a conjugate pair is one, so it is the smaller of the two. The GUI and the CLI report the order with the pole count in brackets, because reporting only the pole count under the label `order` reads as the cap being exceeded. Below scikit-rf 1.12 `model_order_max` was only the exit test of the pole-growth loop and never applied to the initial pole set (3 real plus 3 complex, order 9), so any cap under 9 was inert and a cap above it could be overshot by one batch of added pairs. `universal._auto_fit()` passes the initial counts 1.12 would compute itself, which fixes the first half on older versions and is inert on 1.12, and the second half is why the dependency floor is `scikit-rf>=1.12`.
* Resistor thermal noise is keyed on `ir.physical` (`netlist.py`): a universal macromodel's resistors are fit artifacts and are emitted with `noisy=0` in both dialects, while a structure model's resistors are real loss and keep their noise. The reasoning and the measured numbers are in the comment block above `netlist._NOISY_OFF`. `Element.noisy` overrides that per element (None follows `ir.physical`), and `netlist._silenced()` is the one place both renderers ask.
* `ConverterState.thermal_noise` (universal mode, off by default) appends the passive's thermal noise, kT(I - S S^H) at the ports, through `noise.add_thermal_noise()`, called by the engine after the model response and before the DC check, so the check covers it. `noise.state_space()` rebuilds the fit's real (A, B, C, D, E) from scikit-rf's public pole and residue attributes (the layout of its private `_get_ABCDE`), and `noise.spectral_factor()` solves the bounded-real Riccati equation with `scipy.linalg.solve_continuous_are` in time normalised to the largest pole, with V0 the Cholesky factor of I - D D^T. The generator is N noisy 0.25 ohm resistors (`Element.noisy=True`) driving a copy of the state dynamics, injected into each port's sensor node `s_n` of the scikit-rf realisation at 2/sqrt(Z0) per unit of noise wave, and found by `noise._port_sensors()` from the 0 V source and reference resistor of each port. Each state is rescaled so the gains that drive it and the gains that read it meet in size, with a complex pair tied to one factor, because VACASK does not equilibrate its matrix (1.4 % off at low frequency without it). Before anything is added, V V^H is checked against I - S S^H on DC, the data band and four decades either side (`noise.CHECK_TOL`, 1e-6 kT). A model that is not strictly passive, has a proportional term or fails the check gets no generator, `Results.noise.ok` is False with the reason (naming D when min eig(I - D D^T) <= 0, since enforcement cannot fix that), the engine adds that reason to `messages`, the GUI refuses Export and the CLI writes nothing and exits non-zero. Any failed CLI conversion also removes the files an earlier run left at its output paths (`cli._remove_stale`), except those the same run wrote, so a Makefile cannot take a stale netlist for the result. Its notes go into `CircuitIR.notes`, which the renderers print in full after the provenance comments. `_PLAN_UNIVERSAL_NOISE` carries the extra stage, so the default plan's progress fractions are unchanged. `tests/test_noise.py` solves the emitted circuit with its own AC noise analysis and compares every port and correlation with Bosma's formula.
* The bundled `netlist/` examples are `bpf_ihp-sg13g2.s2p` at `--order 13` (`two_port`), `wpd_ihp-sg13g2.s3p` at `--order 13` (`three_port`) and `blc_ihp-sg13g2.s4p` at `--order 8` (`four_port`), exported with `--format both`. The rendered float tails depend on the BLAS the fit ran on, so a regeneration on another platform can differ in the last digits without anything being wrong. Since 0.1.13 every value is written at full precision (below), so a file regenerated on another platform differs in the last digits of many numbers.
* The header of both dialects names the snp2le version (`snp2le.__version__`, in `netlist.render_ngspice` and `render_vacask`), so a netlist that ends up in a testbench or a paper can be traced to the tool that wrote it. Every release changes that one line of every netlist, so the option-space dump and the `netlist/` re-export compare two versions with it normalised.
* Element values are written as the shortest text that reads back as the same double (`netlist._num`, Python's `repr`). A universal realisation relies on cancellation between its controlled-source gains, and the 10 significant digits written up to 0.1.12 could break it: a synthetic 2-port (a 30 degree line, a 0.2 pF shunt and 5 ohm, 1 to 20 GHz) missed its own model by 2.2e-4 in S at order 20, 1.0 at order 24 and 6.7 at order 40, solved from the netlist text. VACASK's `acsp` on the same netlists read 9.5e-5, 0.27 and 1.3, and 4.4e-10, 7.1e-7 and 3.5e-6 at full precision. The bundled examples and real EM data were not affected (1.4e-8 at most). The text now reproduces the IR exactly, so the netlist is as close to the model as the realisation itself, 9.5e-6 at order 24 on that 2-port.
* A network whose ports do not share one real reference impedance is renormalised to 50 ohm (`io.REFERENCE_Z0`) before anything else, with a note. Such a network comes from a Touchstone 2.0 `[Reference]` line, from HFSS port impedances, which scikit-rf reads complex and per frequency, or, from scikit-rf 2.2 on, from a Touchstone 1.1 option line with one R per port. The structure extractors, `mna.rlc_sparams`, the traces and the tolerances take port 1's z0 for every port. With its ports at 50, 75 and 100 ohm the center-tapped coil came out with an element 70 % off, and at 50 / 75 ohm the 500 pH coil's wideband RMS error read 0.127 instead of 5.0e-3 and a data trace of its pi model was 128 % off in the median. A universal fit was right already, since scikit-rf writes one port resistor per port, and it now refers to 50 ohm like the rest. A network with one real reference on every port and at every frequency, 75 ohm included, is passed on as it is. scikit-rf below 2.2 reads a Touchstone 1.1 option line with one R per port as its first R on every port, another device, which put the 500 pH coil's universal netlist 0.126 rms off the device against a fit error of 7e-5. `io.load_touchstone` therefore refuses an option line whose R values the loaded network does not carry (`io._check_option_references`). On 2.2 and later that never happens, since scikit-rf there reads the line as written or itself refuses a count that does not match the ports.
* A 0 Hz (DC) sample is dropped before every fit and extraction, since it breaks the Y-/ABCD-parameter extraction and the MNA rebuild, and a vector fit extrapolates to DC from the samples above it. A coil's DC resistance then comes out tens of percent off (the bundled `ind_d20` at order 13: 1.29 ohm against the file's 1.096 ohm, 20 ORCA inductors at order 20: 20 % in the median).
* The DC pin (`dcpin.add_dc_pin()`, `ConverterState.dc_pin`, on by default) makes a universal model meet the file's 0 Hz sample: Y = Y_fit + dY / (1 + s/wc) with dY = Y_dc - Y_fit(0), Y_fit(0) from the final `vf` (`model_sparams(vf, [0.0])`). Solved as a circuit, the pinned netlists of the bundled examples meet the target to 7e-13 in S. The engine calls it after the noise generator, in the `dc` stage, so no plan or progress fraction changes. Per port j a VCCS of gain 1e-6 (`dcpin._COPY`) copies V(p_j) onto `dcp_d<j>`, loaded by 1 ohm (`noisy=False`) and 1/wc farad, and per nonzero dY_ij a VCCS of gain dY_ij / 1e-6 from p_i to ground reads V(dcp_d<j>). With a copy gain of 1, VACASK solved the pinned coil at order 13 4e-7 off at 1 THz (1.7e-8 at 100 GHz) and ORCA 1003 at order 20 2e-7 in band, while the same netlists without the pin and Ngspice with it were exact. The errors were identical to the last digit for node scalings that kept V(d) the same, so it is how VACASK factors the whole matrix, not rounding in the pin path. Every copy gain from 1e-4 to 1e-9 gave 1e-15 on all seven cases tried. The target is S(0) taken real, symmetrised and clipped by eigenvalue to +-`dcpin.DC_SIGMA`, a mode at -DC_SIGMA or below being a short the pin refuses by name. `dc_island_leak` adds a conductance through the projector on the eigenvectors of Y_dc below 10 times the clip's floor (1e-7 S at 50 ohm). `dcpin.pinned_sparams()` gives the pinned S as (2I + (I + S) M)^-1 (2S - (I + S) M), M = h R^1/2 dY R^1/2, which needs no (I + S)^-1 where the fit shorts a port. The pin is refused if the band moves by more than the fit's RMS error, or if sigma_max reaches 1 anywhere the fit stays below it on a grid from fc/1000 to the top of the band plus the band itself. The engine then runs the DC check on the pinned IR and, if only the pin made it singular, takes the pin back out (`engine._pin_dc`): the WPD with a 0 Hz point prepended, at order 6, has Y_fit(0) at 566 S in one mode, which the pin would cancel. `model_s` and `rms_error` describe the pinned netlist, `passive`, `sigma_max` and the noise generator stay the fit's. `Results.dc_pin` is a `DCPinHealth`, None when the pin did not apply (structure mode, the option off, no finite 0 Hz sample). The window has no control for `dc_pin_fc` and `dc_island_leak`, so `engine._pin_settings()` appends any that differs from its `ConverterState` default to the pin's message, whatever the pin's outcome, in ASCII like every core message. `ConverterState.from_json()` reads `null` for either as the default and refuses a value that is no number, since `true` would read as 1, while a number out of range, NaN included, loads and skips the pin with a note. A state built in code is not checked: `dcpin.add_dc_pin()` takes whatever `float()` reads (`True` as 1, `"1e3"` as 1 kHz) and skips the pin with a note for anything else or a value out of range. `tests/test_dc_point.py` solves the emitted circuit at 0 Hz and in the band.
* What the pin costs is below its corner. A transient settles to DC on the scale tau = 1/(2 pi fc), 1 ms at 160 Hz: the pole is wc (G_dc + G_ext) / (G_fit + G_ext) with G_ext the circuit around the port, so the bundled coil between 50 ohm ports settles with 0.85 ms, and the noise generator, built from `vf`, carries the fit's DC conductance below a few kHz. `--dc-pin-fc` trades the first against the band: at 10 kHz the band of the ORCA inductors at order 20 moved by up to 4.5e-5 instead of 7.2e-7.
* The lossless branch-line coupler (no *Resistive loss*) puts its four arm inductors in a loop whose current is undetermined at DC: VACASK aborts the operating point on a zero pivot and Ngspice falls back to gmin stepping. `branchline._LOOP_R`, a noiseless 1 uohm in series with the first arm, fixes the loop current and moves S by about 1e-8. `tests/test_core.py` checks the DC operating point of every extracted structure on the examples it is meant for, and `tests/test_inductor_wideband.py` that of the two wideband fits. Mismatched pairs, such as an inductor or MIM-cap model of the band-pass filter, are singular and not checked.
* The transmission-line ladder uses 2 L-cells by default (`N_SEGMENTS` in `snp2le/core/structures/tline.py`) and can be set from 1 to 10 stages.
* `inductor-wideband` and `inductor-ct` port Volker Muehlhaus' inductor_fit ([lumpedmodel](https://github.com/VolkerMuehlhaus/lumpedmodel), used under Apache-2.0 with his permission). `structures/inductor_fit.py` is the fit: analytic seeds from the pi (2-port) or delta (3-port) decomposition, then `scipy.optimize.least_squares` on log10 of the element values over the data up to 1.2 x the self-resonance frequency, from the seed plus two perturbed starts with a fixed random seed, so a fit is reproducible for one set of numpy, scipy and BLAS. Another set can settle elsewhere along directions the data barely constrains: in IIC-OSIC-TOOLS (numpy 2.5, scipy 1.18) the bundled center-tapped fit has L_s,h and k 4.5 % and R_skin2 2.3 x away from Windows (numpy 2.4, scipy 1.17), at a 0.2 % lower cost, while L, Q, the SRF and the well-determined elements agree within 0.3 %. The skin section whose corner lies above the band and the split between L_s,h and k are those directions. By default the fit chooses 1 to 3 coil segments (the fewest within 10 % of the best cost), decides port and half-coil symmetry from the data (5 % threshold), and keeps a 2-port substrate coupling only if it improves the cost by more than 10 % and passes a plausibility check. `structures/inductor_wideband.py` turns the totals into one set of elements per segment, with the substrate network distributed over the coil nodes, and couples every half-1 cell to every half-2 cell with k/segments, which is the fit's M/segments^2 per cell pair. The rebuilt response matches the fit's own model function to 1e-9 in S (`tests/test_inductor_wideband.py`). A value the fit puts below the netlist's floor is raised to it (`netlist._LIMITS`, 1 aF for a capacitor), which moves the netlist off the fit: the basic fit of `ind_d20_w7_sp3_nw1_r10_ihp-sg13g2.s2p` ends at its C_s bound of 0.1 aF, and the 1 aF in the netlist moves S by 2.1e-4, well inside the fit's own error. Its k is the effective coupling including the center tap lead inductance, which terminal data cannot separate from M. A full fit takes 2 s (2-port) to 6 s (center tap) on the bundled examples, the basic model under 1 s. The coupled half coils are stamped entry by entry (`inductor_fit._stamp_coupled`), in the summation order of the einsum over every node and branch pair it replaced, so the bits are the same while a 10-segment center-tap fit went from 605 s to 37 s on one machine. The dense SRF grid is evaluated in chunks of 2000 frequencies (`_on_grid`), which took that fit's peak memory from 1.9 GB to 0.34 GB. A values table longer than 12 rows is shown in two columns (`design_view._ONE_COLUMN_ROWS`).
* inductor_fit's options are all ported: a fixed segment count (`coil_segments`, 1 to 10), a fixed substrate variant (`substrate`), the peak-Q weight A and the shunt accuracy K (`peak_q_weight`, `shunt_accuracy`, defaults 2 and 0.01), and the center tap port (`center_tap`). 0 and "auto" in `ConverterState` leave the choice to the fit, and `inductor_fit.check_options()` is the one place that refuses an impossible set (basic with more than 1 segment, basic or the 3-port with substrate coupling), which the CLI calls before it reads a file and the engine reaches through the fit. The center tap defaults to the port the low-frequency data puts in the middle of the coil: with the other two ports grounded, current from a coil end mostly leaves through the nearby center tap, so the two coil ends share the weakest transfer admittance (`inductor_fit._center_tap_hint`). The fit reorders the data to (end, end, tap), and the IR keeps the file's port order, so the pins match the EM ports. A deliberately wrong port still fits and says which port the data points at. The GUI page offers *Basic model*, *Segments* 1 to 3 (*Center tap* for the 3-port), and the two weights as tick boxes at their defaults. The substrate variant, other weights and more segments are CLI only, and the GUI always sends the values its controls show, so a hand-edited design cannot carry a hidden option into a GUI conversion.
* `fit_universal` points `sys.stdout` and `sys.stderr` at throwaway buffers during the fit (`universal._QUIET`), since scikit-rf reports through warnings, which Python writes to `sys.stderr`. The streams belong to the whole process, not to one thread, so while the GUI's worker fits, anything the GUI thread writes to them is discarded too, most visibly the traceback PySide6 prints when a slot raises. Note that when debugging a GUI problem that only shows up during a fit. Every alternative (a `warnings.catch_warnings`, a logging filter) is just as process-wide, and a thread-aware stream proxy would mean replacing `sys.stderr` from library import. A library caller can run conversions in parallel threads, and a save-and-restore per call then breaks: the second fit saves the first one's buffer as the original and puts it back last, so the program never prints again. `process_state.ProcessSetting` holds the redirect from the first fit in to the last one out instead. `warnings.catch_warnings` and a raised logger level save and restore the same way, so swapping the redirect for them would only move the problem: in a test with 16 conversions in 8 threads they left the warning filters and the scikit-rf log level changed for good.
* scikit-rf's `auto_fit` can cycle for good. Its adding and skimming loop has no pass limit, its accuracy exit compares a peak error that is never updated inside the loop, and a pass can skim what it adds, so on some EM data it alternates between two pole sets (6 of 3,200 ORCA fits at `model_order_max=20`, scikit-rf issue 1452). `universal._RelocationLimit` counts the pole relocations of the one fit, as a wrapper on the instance so that parallel fits keep their own counts, and stops it past `_AUTO_FIT_MAX_RELOCATIONS` (250, converging fits need 8 to 120 and the bundled examples at most 26, but the refit that includes `tline_100um`'s 0 Hz point cycles at order 10). `_refit_stuck()` then redoes the fit with `vector_fit` at the pole counts it had reached, and the messages say so. Another cap is no cure, since one of those files cycles at 20, 21 and 22.
* A conversion cannot be cancelled once started. The long call inside it (`VectorFitting.auto_fit`) is not interruptible, so a Stop button could not honour its own label. Superseding requests are coalesced instead, and the window stays usable meanwhile.
* The title bar's **View** switch is a row of exclusive buttons (`widgets.SegmentedSwitch`), one per view, rather than a drop-down: a drop-down keeps its other entries behind a popup, so nothing on the opening screen said the Plot view existed. `TopBar.set_view()` emits `view_changed` exactly as a click does, which is what carries the window along with the plot pop-out, dock, reset and simulation-import paths, and it stays silent when the requested view is already selected. A `&` in a segment label has to be doubled, since a button label reads it as a mnemonic marker and swallows it.
